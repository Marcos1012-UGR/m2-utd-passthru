### `macchina-passthru.cpp`

Modificar:

* `PassThruOpen()`

  * → llamar a `VCI_Open()`.

* `PassThruClose()`

  * → llamar a `VCI_Close()`.

* `PassThruConnect()`

  * → eliminar `usbcomm::isConnected()`.
  * → mantener creación del `channel`.
  * → el canal terminará llamando a `VCI_Connect()`.

  * → eliminar `usbcomm::isConnected()`.
  * → delegar en `channel`.

  * → eliminar dependencia directa de `usbcomm`.

  * → eliminar dependencia directa de `usbcomm`.

  * → mantener como API J2534, pero eliminar cualquier dependencia de hardware Macchina.

* `PassThruStopPeriodicMsg()`

  * → igual.

  * → eliminar dependencia de `usbcomm`.
  * → delegar en `channel`.

* `PassThruStopMsgFilter()`

  * → igual.

* `PassThruSetProgrammingVoltage()`

  * → pasar a `VCI_SetProgrammingVoltage()`.

* `PassThruReadVersion()`

* `PassThruGetLastError()`

  * → mantener, aunque conviene corregir después la copia del `\0`.

* `PassThruIoctl()`

  * → sustituir acceso directo a hardware por `VCI_Ioctl()`.

# 🆕 CREAR

### `vci.h`

Nueva abstracción de hardware:

```text
VCI_Open()
VCI_Close()

VCI_Connect()
VCI_Disconnect()

VCI_Send()
VCI_Receive()

VCI_StartFilter()
VCI_StopFilter()

VCI_SetProgrammingVoltage()

VCI_Ioctl()
```

Por ahora serán **stubs**, sin USB, Arduino, CAN ni K-Line.

---

### `vci.cpp`

Implementación de esos `VCI_*`.

En esta fase:

```text
VCI_Open()       → cambia estado a abierto
VCI_Close()      → cambia estado a cerrado

VCI_Connect()    → registra protocolo/baudrate y devuelve OK
VCI_Disconnect() → libera conexión

VCI_Send()       → registra/descarta el mensaje
VCI_Receive()    → devuelve ERR_BUFFER_EMPTY

VCI_StartFilter() → stub
VCI_StopFilter()  → stub

VCI_SetProgrammingVoltage() → stub
VCI_Ioctl()       → stub
```

Así podemos probar **toda la cadena J2534 sin tener todavía el Arduino**.
